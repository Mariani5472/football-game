P6 — Package Identity / Conflict System
Isso é importante porque você introduziu uma regra nova:
uma World pode possuir vários arquivos/pacotes desde que eles não sejam conflitantes.

Exemplo:
World
│
├── Brazil
├── Argentina
├── Bolivia
└── CONMEBOL

Mas:
Brazil
Brazil

não deveria ser permitido.
Precisamos então de uma identidade formal.
Package metadata
Algo como:
{
  "id": "country.brazil",
  "type": "country",
  "version": "1.0.0",
  "schemaVersion": 4,
  "dependencies": [],
  "provides": [
    "country:brazil",
    "cities:brazil",
    "clubs:brazil"
  ]
}

CONMEBOL:
{
  "id": "confederation.conmebol",
  "type": "competition",
  "version": "1.0.0",
  "dependencies": [
    "continent.south-america"
  ],
  "provides": [
    "competition:libertadores",
    "competition:sudamericana"
  ]
}

Então o conflito não é:
arquivo == arquivo

É:
package identity
        +
provided entities
        +
dependencies

Isso permite futuramente:
Brazil v1
Brazil v1.1

como atualização/substituição controlada, enquanto:
Brazil
Brazil

é conflito.

SQL pagination

para uma tabela com 100k jogadores.

OFFSET ?

ou cursor pagination quando fizer sentido.
