# ROADMAP — FOOTBALL GAME EDITOR

## Objetivo

Transformar o editor em uma ferramenta real para construir e manter o `world.db`.

Fluxo final:

```
world.db
  -> leitura real
  -> edição
  -> persistência
  -> validação
  -> export
  -> reabertura sem perda
```

O editor NÃO deve usar mocks como fonte principal e NÃO deve acessar SQLite diretamente pelos componentes React.

# ARQUITETURA FINAL DESEJADA

Não criar uma tela para cada uma das 217 tabelas.

Usar:

```
217 tabelas
  |
  +-- tabelas simples --------> CRUD genérico
  |
  +-- N:N / associações ------> Relation components
  |
  +-- agregados complexos ----> Editors especializados
```

Estrutura:

```
apps/editor
  UI

editor/application
  operações do editor

world/database
  SQLite

world/domain
  modelos/regras

world/validation
  validação

engine
  simulação
```

O engine não deve conhecer React nem detalhes do editor.

